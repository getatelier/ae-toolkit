# PRD: Roadmap Phase 5 — Night-Shift Runtime

## Overview

Phase 5 of the AET roadmap (`content/fable-review/09-2026-07-10-roadmap.md`): make the overnight shift **survive its own failures**. Today a task that fails is marked `failed` and left there until morning — no classification, no retry, no quarantine, no hang detection, and a wall-clock timeout that punishes slow-but-alive work as harshly as a wedged process. This phase installs four runtime mechanisms so an unattended queue finishes without a babysitter: a **failure taxonomy in code** (`environment / flaky / design / timeout / canceled`) with a **normalized failure signature**; a **circuit breaker** — per-task (the same signature 3× ⇒ quarantine, because a deterministic failure will not fix itself) and systemic (the same signature across several tasks ⇒ stop spawning, because one broken environment must not burn the whole queue); **`--on-failure=triage`** (the default) so each failure is classified and either requeued (flaky/environment) or quarantined (design), and the shift continues; and a **stall watchdog on event silence**, not the clock, using frh-03's process-group kill for enforcement. Cost is captured **per task on the ledger for analytics only** — it never gates, kills, or triages anything (owner decision 2026-07-15, overriding the roadmap's "budget ceilings with kill-and-triage on overrun"). The roadmap's thesis for this phase: this is what makes scaling the night shift *safe* — an injected failure and an injected stall should cost the queue two tasks, not the whole run.

## Goals

- **G1**: The night shift survives a failure — every terminating session is classified into exactly one taxonomy category and given a stable signature, and by default a failure is triaged (requeued or quarantined) so the rest of the queue runs to completion unattended instead of leaving a `failed` task to rot until morning (R-1, R-2, R-7, R-8).
- **G2**: Deterministic failures stop burning the queue — a per-task breaker quarantines a task whose failures repeat the same signature 3×, and a systemic breaker stops new spawns when one signature recurs across distinct tasks; breaker counts are persisted to the ledger so a deterministic failure stays quarantined across shifts rather than being re-attempted every night (R-3, R-4, R-5, R-6).
- **G3**: Hangs are caught by silence, not the clock — an event-silence watchdog kills a stalled session (no output for a configurable interval) via frh-03's process-group kill and classifies it `timeout`, while a generous wall-clock `--task-timeout` is retained only as a coarse backstop beneath it; a slow-but-alive session that keeps emitting is never killed for being slow (R-9, R-10).
- **G4**: Cost is observable per task — per-task token/cost is rolled up from stage telemetry onto the task's ledger record at close, for analytics and the morning desk; it is a field on every record and **never** a failure reason, exit trigger, or triage input (R-11).
- **G5**: The resilience is demonstrated, not asserted — a recorded rehearsal shows an overnight run with one injected deterministic failure and one injected stall finishing the rest of the queue unattended, with both incidents classified and costed on the ledger (R-12, R-13).

## Non-Goals

- **No budget enforcement of any kind.** No cost ceilings, no kill-on-overrun, no budget-triggered triage. This deliberately overrides the roadmap doc-09 Phase 5 line "budget ceilings per task with kill-and-triage on overrun" (owner decision 2026-07-15). Cost is analytics-only (R-11): a field on every ledger record, never a control signal. Consequently `budget` is **not** a failure taxonomy category — a task cannot fail *because of* cost when cost terminates nothing.
- **No estimated or mid-session cost.** `aet-work/lib/usage.py`'s standing rule holds — usage is parsed post-hoc from captured CLI output at session exit and is `None` when unmeasurable (null for Kimi, which has no published per-token price); Phase 5 introduces no proxy-dollar figure and no streaming cost meter. The stall watchdog (R-9) measures output *silence*, never spend.
- **No second storage backend.** Breaker state (R-6) and the per-task cost rollup (R-11) ride the existing git-refs ledger / task records; the standing fence (no storage backend beyond git-refs, roadmap doc 09) holds.
- **No harness/model routing for the triage session.** The roadmap's "cheap triage session" implies a small model, but cross-vendor routing is Phase 6/7 and only Claude Code is conformant today. Phase 5 runs triage on the **active** adapter and reserves the routing hook (a `triage` route key), mirroring how Phase 1 parsed the `routing` axis before any second adapter existed. Actually running triage on a cheaper harness is Phase 6/7 scope.
- **No change to the gate-evidence contract.** The four verdict kinds (`qa`/`review`/`cso`/`sync-docs`, frh-10 / ADR-019) and their schemas are untouched. Failure classification is orthogonal to gate verdicts: a gate *fail* is a recorded verdict; a *failure* is a non-zero/killed session. Phase 5 classifies the latter.
- **No morning-desk work.** Phase 4 (`twe-*`) owns `aet desk`. Phase 5 only guarantees the facts the desk will read — per-task cost (R-11) and the `quarantined` state (R-3) — are on the ledger. Desk rendering of quarantine/cost is Phase 4's concern.
- **No heuristic classification beyond the fixed taxonomy.** The classifier is a closed menu of five categories (determinism over runtime discretion, ADR-020); it does not learn or infer new categories. An unclassifiable failure takes a fail-safe default (see Open Questions), it does not mint a new class.
- **No new agent loop, sandbox, or daemon; no DAG/parallel stage graph; no runtime condition DSL.** Standing fences (roadmap doc 09) hold. Retries are re-spawns of the existing session runner; parallelism stays *across* tasks in the existing `run_batch` pool, never *inside* a task.

## Requirements

- **R-1**: A **failure taxonomy in code** — a new pure module `src/aet/failure.py` classifies a terminating agent session into exactly one of `environment | flaky | design | timeout | canceled`, from the signals already on hand at the finalize path (exit code, the bounded captured tail already kept by `_run_with_live_tee` in `src/aet/cli/orchestrator.py`, the stage, and whether a required verdict was recorded). `canceled` covers an orchestrator-initiated shutdown (the `_shutdown_requested`/SIGTERM path in `src/aet/cli/orchestrator.py`); `timeout` covers a watchdog or wall-clock kill (R-9/R-10); `environment` vs `flaky` vs `design` partition the rest. Classification is a pure function of its inputs (unit-testable without a live session) and returns a fail-safe default when signals are ambiguous (Open Questions).
- **R-2**: A **normalized failure signature** — `failure.py` derives a stable, short signature from `(stage, normalized-error-key)`, where the error key strips volatile spans (paths, PIDs, timestamps, hex/uuids, line/col numbers) so two runs of the *same* deterministic failure produce the *same* signature and two genuinely different failures do not. The signature is the deterministic key the breaker (R-4/R-5) counts; it is unit-tested for stability (identical failures collide) and discrimination (distinct failures separate).
- **R-3**: A **`quarantined` task state** — a new terminal-until-human state added to `LEGAL_TRANSITIONS` (in `src/aet/queue.py`), distinct from `failed` (which is retry-eligible: `failed → {in_progress, ready, blocked, abandoned}`) and from `abandoned` (human-terminal). Transitions: `{in_progress, failed} → quarantined`, and `quarantined → {ready, abandoned}` only (a human un-quarantines after a fix, or abandons). `quarantined` is **non-actionable** — `has_actionable_tasks` and the spawn selector in `run_batch` never pick it, so the breaker's decision is enforced by the state machine, not remembered by the orchestrator (ADR-011 determinism). `aet-state`'s transition validation, derived-state reconciliation (`src/aet/cli/state.py`), and the panel's state rendering learn the new state. Authored as **ADR-030**, which extends ADR-011 (the deterministic state model) and applies ADR-020 (code-enforced determinism); it is consistent with ADR-005's unattended-execution model but does **not** modify its gate-stop list.
- **R-4**: A **per-task circuit breaker** — the finalize path records each task's failure signatures; when a task accumulates the **same** signature 3× (a deterministic failure that retrying will not fix), the task is driven to `quarantined` (R-3) instead of being requeued again. The threshold (default 3) is a named constant, not a magic number. A task whose successive failures have *different* signatures is not breaker-quarantined by this rule (it is still bounded by an overall attempt cap — Open Questions).
- **R-5**: A **systemic circuit breaker** — when a single signature recurs across **N distinct tasks** in a shift (default N=3; one broken environment failing task after task), a shift-level breaker trips and `run_batch` stops spawning new tasks, draining only what is already running, then exits with a named "systemic breaker: signature `<sig>` × `<n>` tasks" report. This is the safety valve that turns a broken-environment night from "20 failed tasks and a drained budget" into "3 failures and a clean stop."
- **R-6**: **Breaker persistence** — per-task signature counts (R-4) live on the task's ledger record, and the systemic signature tally (R-5) is persisted to the git-refs ledger (a dedicated breaker projection or ref; storage shape is a plan-level choice, but **no new backend** — Non-Goals), so a deterministic failure that quarantined a task last night is still quarantined tonight and is not blindly re-attempted. Persistence is what makes `design` failures stay put across shifts rather than re-entering the queue every run.
- **R-7**: **`--on-failure={triage|continue|halt}` on `aet run`, defaulting to `triage`.** On a task failure the orchestrator (a) classifies it (R-1) and computes its signature (R-2), (b) consults the breaker (R-4/R-5), and (c) if not breaker-quarantined, spawns a **cheap triage session** on the active adapter that confirms the class and routes the outcome: `flaky`/`environment` ⇒ requeue (R-8), `design` ⇒ `quarantined`. The shift continues regardless. `continue` reproduces today's behavior (mark `failed`, keep going, no triage session); `halt` stops the shift on first failure. Default `triage` is the night-shift default because it maximizes unattended completion, capped by the breaker so triage cannot loop forever.
- **R-8**: A **requeue path** — a failure triaged as `flaky` or `environment` is requeued (a legal `failed → ready` transition via `aet-state`, preserving the sole-writer rule) and re-attempted by the pool, its signature recorded so R-4 can still quarantine a "flaky" that is actually deterministic. Requeue is bounded: a task is retried at most up to the per-task breaker threshold (R-4), after which it quarantines.
- **R-9**: A **stall watchdog on event silence** — the session runner tracks the wall-time since the last line of session output (the `_run_with_live_tee` reader loop in `src/aet/cli/orchestrator.py` already sees every line and keeps a `last-output` clock trivially); when output goes silent for a configurable interval (default 300 s, `--stall-timeout`), the session's process group is terminated via frh-03's `_terminate_process_group` (`src/aet/cli/orchestrator.py`) and the failure is classified `timeout` (R-1). Because the watchdog lives where stdout is visible — inside the single-plan session runner, not the batch parent (which spawns children without a stdout pipe, `src/aet/cli/orchestrator.py`) — it observes real liveness, so a session emitting progress is never killed no matter how long it runs.
- **R-10**: The **wall-clock timeout is retained as a coarse backstop**, not the primary control. `--task-timeout` (`src/aet/cli/orchestrator.py`) stays for the pathological case (a wedged process still holding an open pipe but emitting nothing the reader can see, or a runaway that streams forever), but its default is raised well above the stall interval so the event-silence watchdog (R-9) is what fires in normal operation. Both kills route through the same `timeout` classification and the same process-group termination; the watchdog is primary, the clock is the floor.
- **R-11**: A **per-task cost rollup to the ledger, analytics-only** — at task close the orchestrator sums the task's stage telemetry (`token_count` / `cost_estimate`, already emitted per session by `_emit_stage_session` in `src/aet/cli/orchestrator.py` and summed per-run by `_usage_aggregates`) into a per-task total and writes it onto the task's ledger record. Null is preserved honestly (an all-null task records null, never zero). This figure is for the desk and analytics only; **no code path reads it to gate, kill, throttle, or triage** (the budget Non-Goal). It closes the roadmap's "per-task cost captured to the ledger" as pure observation.
- **R-12**: The **phase exit gate is demonstrated end-to-end and recorded** in `docs/audits/` (matching the frh-14 / ewl-06 / twe-07 rehearsal precedent): an overnight run over a small queue with (a) one **injected deterministic failure** (a fixture plan that fails the same way every attempt) and (b) one **injected stall** (a fixture that goes output-silent) finishes the remaining tasks unattended; the deterministic failure is shown quarantined by the per-task breaker after its retries, the stall is shown killed by the event-silence watchdog and classified `timeout`, and both incidents carry a per-task cost figure on the ledger.
- **R-13**: **Tests** cover: classification into each of the five categories and the fail-safe default (R-1); signature stability and discrimination over volatile-span normalization (R-2); the `quarantined` state's legal and illegal transitions and its non-actionability in the spawn selector (R-3); per-task quarantine at the 3× threshold and no-quarantine on differing signatures (R-4); systemic breaker tripping at N distinct tasks and stopping spawns (R-5); breaker persistence surviving a simulated shift restart (R-6); `--on-failure` routing for all three modes and triage requeue-vs-quarantine (R-7, R-8); the stall watchdog firing on silence while a still-emitting session is spared, with the wall-clock backstop intact (R-9, R-10); and the per-task cost rollup from a synthetic telemetry set including the all-null case (R-11).

## User Stories

- As the owner running AFK overnight, when one task hits a broken dependency the shift doesn't stall on it — the failure is classified and either retried or quarantined and the rest of the queue finishes, so I wake up to N-1 merges and one clearly-labeled quarantine instead of a dead run stopped at task 3 (satisfies: R-1, R-7, R-8).
- As the owner, when the same deterministic failure keeps recurring the factory stops throwing agents (and money) at it — the task quarantines after 3 identical-signature failures, and if the same signature is hitting task after task the whole shift stops with a named reason rather than grinding through the entire queue on a broken environment (satisfies: R-2, R-4, R-5).
- As the owner, a quarantine sticks — a design-level failure that quarantined last night doesn't silently re-enter tonight's queue to fail again; it waits for me to fix it and explicitly un-quarantine it (satisfies: R-3, R-6).
- As the owner, a genuinely slow task that's still making progress is left alone, while a wedged one that's gone quiet is killed within minutes — liveness is judged by whether the agent is still emitting, not by a stopwatch that can't tell working from hung (satisfies: R-9, R-10).
- As the owner reviewing at the desk, each task shows what it cost to produce, so I can see cost-per-merged-task over time — but nothing I didn't ask for ever gets killed for being expensive; cost informs me, it doesn't govern the run (satisfies: R-11).
- As the Phase 8 implementer building the scoreboard, per-task cost and per-class failure/quarantine history are already on the ledger, so the ablation table reads existing facts rather than needing new instrumentation (satisfies: R-6, R-11).

## Acceptance Criteria

- [ ] Given synthetic session results, `failure.classify(...)` returns each of `environment | flaky | design | timeout | canceled` for the appropriate inputs, the shutdown path classifies `canceled`, a watchdog/wall-clock kill classifies `timeout`, and an ambiguous input takes the documented fail-safe default (satisfies: R-1).
- [ ] `failure.signature(...)` returns identical signatures for two failures differing only in paths/PIDs/timestamps/line numbers, and different signatures for failures differing in stage or error class (satisfies: R-2).
- [ ] `quarantined` is a legal target from `in_progress` and `failed` and a legal source only to `ready`/`abandoned`; an attempt to transition `quarantined → in_progress` is rejected, and a `quarantined` task is never selected for spawning by `run_batch` (satisfies: R-3).
- [ ] A task fed the same failure signature three times is driven to `quarantined` and not requeued a fourth time; a task fed three *different* signatures is not quarantined by the per-task rule (satisfies: R-4).
- [ ] With one signature injected across three distinct tasks, the systemic breaker trips, `run_batch` stops spawning new tasks, drains the running set, and exits with a named "systemic breaker" report (satisfies: R-5).
- [ ] Breaker counts written during a shift are re-read on the next `aet run` so a task quarantined by a deterministic signature stays quarantined and is not re-attempted (satisfies: R-6).
- [ ] `aet run --on-failure=triage` (and the bare default) classifies a failure and requeues a `flaky`/`environment` one to `ready` while quarantining a `design` one; `--on-failure=continue` marks `failed` and continues with no triage session; `--on-failure=halt` stops the shift on the first failure (satisfies: R-7, R-8).
- [ ] A session that emits no output for longer than `--stall-timeout` has its process group terminated and the failure classified `timeout`; a session that keeps emitting past `--stall-timeout` but under `--task-timeout` is left running; a session emitting nothing and exceeding `--task-timeout` is killed by the backstop (satisfies: R-9, R-10).
- [ ] At task close, the task's ledger record carries a per-task token/cost total equal to the sum of its stage telemetry, with null preserved for an all-null task; no orchestrator code path consults this value to gate, kill, or triage (satisfies: R-11).
- [ ] The R-12 rehearsal — an overnight run with one injected deterministic failure (quarantined by the breaker) and one injected stall (killed by the watchdog, classified `timeout`), the rest of the queue completing unattended, both incidents costed on the ledger — is executed and written up in `docs/audits/` (satisfies: R-12, R-13).

## Technical Notes

**Current reality (grounded 2026-07-15 at `HEAD`).** The failure path is binary and terminal: `_mark_failed` (`aet-work/bin/orchestrator:1125`) transitions a task to `failed` via `aet-state transition`; the `run_batch` pool (`:1249`) *does* continue past a single failure (so "fail-fast halts the shift" is already partly retired), but there is no taxonomy, signature, retry, requeue, quarantine, or triage — a `failed` task simply waits. Timeout is wall-clock only (`--task-timeout` default 3600 s, enforced at `:1483` by `now - spawn_times[task_id] > task_timeout`), and the batch parent spawns child orchestrators with `start_new_session=True` and **no** `stdout=PIPE` (`:1452`), so per-line liveness is visible only inside the single-plan child's `_run_with_live_tee` (`:536`) — which is exactly where R-9's watchdog must live. Cost/tokens are parsed post-hoc from captured output at session exit (`lib/usage.py`), land on `stage` telemetry records as `cost_estimate`/`token_count` (`:337`), and are summed per-run by `_usage_aggregates` (`:422`); there is no per-task rollup and no mid-session cost signal. frh-03's process-group kill primitives (`_killpg` `:73`, `_terminate_process_group` `:82`) already exist and are the enforcement arm for both the watchdog and the wall-clock backstop.

**Anticipated plan decomposition (prefix `nsr`, "night-shift runtime"; finalized at `create-stories`/`plan`).** Roughly seven atomic plans, foundation-first:

- `nsr-01` — `lib/failure.py`: taxonomy classifier + normalized signature, pure + unit-tested (R-1, R-2). No orchestrator wiring. Foundation for all.
- `nsr-02` — `quarantined` state: `LEGAL_TRANSITIONS`, `aet-state` validation + derived-state, panel, ADR; wired but inert (R-3). Blocked by none; unblocks the breaker.
- `nsr-03` — circuit breaker (per-task + systemic) + ledger persistence (R-4, R-5, R-6). Blocked by `nsr-01`, `nsr-02`.
- `nsr-04` — `--on-failure=triage` + triage session + requeue path, triage-by-default (R-7, R-8). Blocked by `nsr-01`, `nsr-02`, `nsr-03`.
- `nsr-05` — stall watchdog on event silence + wall-clock backstop retained (R-9, R-10). Blocked by `nsr-01` (for the `timeout` class).
- `nsr-06` — per-task cost rollup to the ledger, analytics-only (R-11). Independent (touches telemetry/close path only); can run in parallel.
- `nsr-07` — exit-gate rehearsal, written up in `docs/audits/` (R-12, R-13). Blocked by all.

**Architecture decisions (authored at scope-validation, 2026-07-16 — `docs/adr/030-night-shift-failure-handling.md`, `docs/adr/031-runtime-observation-vs-enforcement.md`; 029 is claimed by Phase 4's `twe-08`).**

- **ADR-030 — Night-shift failure handling: quarantine state + circuit breaker + triage-by-default.** Records the `quarantined` state (extends ADR-011, applies ADR-020; consistent with ADR-005 without modifying its gate-stop list), the per-task and systemic breaker semantics and thresholds, and why `triage` is the default `--on-failure` mode. Rationale is the ADR-020 razor: the retry-vs-quarantine decision is made by code on a deterministic signature, not remembered by an AI mid-shift.
- **ADR-031 — Runtime observation vs enforcement: budget is analytics-only; stalls are detected by event-silence, not the clock.** Records the owner's 2026-07-15 override of the roadmap's budget-ceiling enforcement (cost observes, never governs) and the event-silence-over-wall-clock choice with its rejected alternative (a pure wall-clock timeout punishes slow-but-alive work). Grouped because both are the same principle — observe honestly, enforce only on evidence, never on a guess or a stopwatch.

## Resolved Decisions (scope-validation, 2026-07-16)

The five open questions are resolved and folded into the plans and ADR-030/031:

1. **Unclassifiable failure → `environment`** (retry-eligible, breaker-bounded) — a disguised deterministic failure still quarantines after 3×. Fixed in nsr-01; revisit only if the rehearsal shows retry waste.
2. **Systemic breaker N = 3 distinct tasks**, matching the per-task threshold; a named constant, tunable later without a contract change. Fixed in nsr-03.
3. **`canceled` is excluded from breaker tallies** — a shutdown-initiated stop is not failure evidence. Fixed in nsr-03 / ADR-030.
4. **Systemic tally persists to `refs/aet/breaker`** on the existing git-refs ledger (no new backend). Fixed in nsr-03 / ADR-030.
5. **`--stall-timeout` is a single global, default 300 s**; per-stage/per-class overrides deferred until the rehearsal shows one global value misfires. Fixed in nsr-05 / ADR-031.

**Scope-validation finding, recorded:** the triage session is *runtime* judgment, which brushes ADR-020's "no runtime conditionals in the engine." Reconciled in ADR-030 — failure is inherently runtime; the breaker's counting/quarantine is deterministic code, and triage is an explicit, sanctioned session whose verdict the engine merely enforces (like a review stage), not a hidden engine branch. `quarantined` plus the five failure terms were added to the CONTEXT.md glossary; no terminology or code-ground-truth conflicts remain.
