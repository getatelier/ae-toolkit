# PRD: Roadmap Phase 4 — The Two Human Ends

## Overview

Phase 4 of the AET roadmap (`content/fable-review/09-2026-07-10-roadmap.md`): attacks the two bottlenecks that bound the factory's throughput — review bandwidth (the exit end) and planning quality (the intake end) — and installs the mechanism that will later let trusted work skip the exit end entirely. Three pieces: **`aet desk`** is the risk-ranked morning cockpit — every `awaiting_merge` task with its evidence bundle, ordered riskiest-first, and actionable in place (merge or abandon). **`aet plan validate`** makes plan quality machine-checkable and turns it into a hard intake gate — a plan that fails validation cannot enter the queue. And the **zero-review-class mechanism** records `work_class` as a plan-time attribute, reads per-class clean-merge track record from the ledger, and can auto-merge an enabled class — shipped OFF, auto-merging nothing, because enablement waits for Phase 7's proof data. A fourth piece, added 2026-07-15 from the autonomous-shipping audit, makes the exit end **enforceable**: autonomous merge becomes a fail-closed gate (extending ADR-005) and `aet setup` generates a per-provider merge-guard so an agent cannot self-merge around the toolkit — otherwise the "human decides at the desk" default is only a default. The roadmap's thesis governs the whole phase: drive human touches between plan-approval and review toward zero, and concentrate the human minutes that remain at exactly these two ends.

## Goals

- **G1**: The morning review has a cockpit — `aet desk` surfaces every `awaiting_merge` task with its full gate-evidence bundle, risk-ranked with legible per-task factors (no black-box ordering), and the owner merges or abandons each task from the desk without leaving it (R-1, R-2, R-3).
- **G2**: Plan quality is enforced by code at intake — `aet plan validate` runs structural, R-trace, acceptance-as-evidence, and scope-reference checks; a plan that fails (and is not explicitly acked) cannot enter the queue through any intake path (R-4, R-5, R-6).
- **G3**: Work class is a recorded attribute, and the zero-review exit door exists but is shut — `work_class` is authored at plan time and validated at intake; a policy reads per-class clean-merge track record from the ledger and can auto-merge an enabled class, but ships disabled and auto-merges nothing by default (R-7, R-8, R-9).
- **G4**: The exit gate is demonstrated, not asserted — a recorded rehearsal shows a real review happening in the desk, a failing plan rejected at intake, and the zero-review mechanism present-but-off, with a test proving it would merge only when a class is explicitly enabled and its track record qualifies (R-10, R-11).
- **G5**: The exit-end merge gate is **un-bypassable** — an agent cannot merge a PR by reaching around the toolkit. Autonomous merge is a fail-closed gate even in unattended mode (extends ADR-005), and `aet setup` generates a merge-guard for the **active** harness that refuses an agent-issued `gh pr merge`. Without G5, R-9's "human decides at the desk" default is only a default, not an enforced boundary — the 2026-07-15 autonomous-shipping audit showed an agent self-merging around the pipeline under session auto mode (R-12, R-13, R-14).

## Non-Goals

- No scoreboard, `aet eval`, telemetry ablation, or learning loop (Phase 7). Zero-review stays OFF for the entire phase; **enabling zero-review class #1 is explicitly Phase 7's exit gate**, on Phase 7's track-record data — Phase 4 builds the mechanism and ships it disabled.
- No failure taxonomy, circuit breaker, stall watchdog, or budget ceilings (Phase 5). The desk reads and ranks; it does not classify failures or govern cost.
- No **broad** multi-harness adapter *suite*, `aet doctor --harness` conformance tooling, or cross-vendor review routing (Phase 6). **Carve-out (G5, from the 2026-07-15 audit):** the single **active-harness** merge-guard and the harness-adapter *interface* it establishes are in Phase 4 scope — they are what make R-9's off-by-default human-merge policy actually enforceable rather than merely defaulted. Phase 6 extends that interface to additional harnesses (Kimi/OpenCode) and adds the conformance/`doctor` surface; Phase 4 ships exactly one adapter (the harness it detects, Claude Code first) plus the interface.
- No interactive prompt or TUI for the desk. Actions are explicit, non-interactive subcommands (`aet desk merge <id>`, `aet desk abandon <id>`), consistent with the toolkit's verified zero-`input()`/`stdin` posture (P3 grounding). **P3 Open Question 1's deferred fail-closed-confirm helper stays deferred** — this phase deliberately introduces no blocking prompt for it to attach to (recorded in Open Questions).
- No read-only web surface (`aet serve --read-only`) — Phase 8, trigger-gated ("the desk outgrowing the terminal"). The desk is terminal-only.
- No new merge implementation and no second closure writer. `aet desk merge` and the zero-review auto-merge both drive the existing merge + `aet-state record-merge` closure path (`aet-ship/bin/ship`); the exact merge invocation is an implementation choice for the plan, but `aet-state record-merge` remains the sole writer of the `merged` transition.
- No new evidence schemas and no change to the four verdict kinds (frh-10 `qa`/`review`/`cso`/`sync-docs`). The desk reads existing verdicts; it does not redefine them.
- No re-scoring or redefinition of the work classes themselves — the three PIPELINE.md tiers (Trivial/Normal/Critical) stand as-is; Phase 4 only records the existing tier as a machine-readable attribute.
- No heuristic auto-classification of `work_class`. It is authored at plan/triage time (determinism over runtime discretion, ADR-020); a missing value stays `unclassified` and is never zero-review-eligible.
- Standing fences hold (roadmap doc 09): no daemon, no DAG/parallel stage graphs, no per-workflow state vocabularies, no plugin verifier APIs, no second storage backend.

## Requirements

- **R-1**: A new `aet desk` subcommand (one row in the `aet` dispatcher spec table, `aet-work/bin/aet:SUBCOMMANDS`; new binary `aet-work/bin/desk`). It lists only tasks in state `awaiting_merge` (the state model's "awaiting review" — pipeline exited 0, all required verdicts recorded, waiting on the human merge decision; `docs/PIPELINE.md` Legal Transitions), and annotates each with its **evidence bundle**: the `qa`/`review`/`cso`/`sync-docs` verdicts read from `evidence.evidence_path(task_id, kind)` (`~/.aet/reports/{project-slug}/{task-id}/{kind}.json`), surfacing each verdict's pass/fail, summary, findings count, and test totals. A required stage with **no** recorded verdict is shown as a visible gap, never silently omitted. A `--json` projection mirrors `status --json` for machine consumers.
- **R-2**: The desk is ordered by a **deterministic risk score**, riskiest first, with the contributing factors printed per task so the ranking is legible rather than opaque. The score is a pure function of already-available signals: `work_class` (`critical` > `normal` > `trivial`; `unclassified` ranks elevated — unknown risk needs eyes), plan `size` (L > M > S), the review/cso findings counts and any `fail` or missing required verdict, and ledger signals for the task (`files_modified` count, `tests_failed > 0`). The scoring function is unit-tested for stable ordering against fixed inputs; weights are data, tunable later without changing the contract.
- **R-3**: The desk actions the merge decision through explicit, non-interactive subcommands. `aet desk merge <task_id>` drives the existing merge + closure path (`aet-ship`), and `aet desk abandon <task_id> --reason <r>` records the terminal `abandoned` transition via `aet-state`. Both resolve the task from the live queue and **fail closed** on an unknown id or a task not in `awaiting_merge` (non-zero exit, named error) — the desk never merges or abandons something it cannot positively identify as review-ready. No second closure writer is introduced (Non-Goals).
- **R-4**: A new `aet plan validate [<plan>...]` subcommand runs the full plan-quality check suite (defaulting to all `docs/plans/*.md`, or the named plans):
  - **(a) Structural** — reuse `plan_parser.intake_validation_errors` (id/filename match, unique id, `size` ∈ {S,M,L}, gate-routing keys, `blocked_by` resolvable, no legacy dependency section, atomic-complexity limits).
  - **(b) R-trace coverage** — lift the `aet-plan` skill's prose Check 4 into code: collect the R-ids declared in the source PRD's Requirements section (located via the plan's Context/frontmatter PRD reference) and the `(traces: R-n)` citations in the plan's task list; an in-scope R-id with no covering task and no explicit deferral-with-reason **fails**, and a task citing an R-id absent from the PRD's scope **fails**.
  - **(c) Acceptance-as-evidence** — each acceptance criterion describes an observable/verifiable behavior (not a restated task), and every new source file the plan introduces has at least one **named** test in its self-validation strategy (the `aet-plan` `plan` Validation-strategy gate, mechanized).
  - **(d) Scope-reference resolution** — every `docs/adr/NNN` reference in the plan resolves to an existing ADR file, and flagged domain terms resolve against `CONTEXT.md`.
- **R-5**: The validate gate **blocks fail-closed with a recorded-ack escape hatch**. Any failing check rejects the plan, *except* where the plan carries an explicit acknowledgment marker — `⚠️ VALIDATE ACK: <check-id> — <reason>` — that overrides that specific check with a recorded reason, mirroring the existing `⚠️ ATOMIC OVERSIZED` convention (`plan_parser.validate_size`). An ack marker missing its reason does not override (fail-safe). Acks are per-check-id and never blanket.
- **R-6**: A plan failing validation (without a matching ack) **cannot enter the queue through any intake path**. `aet-work add` — which does **not** validate today (confirmed: `aet-work/bin/add` checks only footer stage and duplicate/settled membership) — `init-queue`, and `sync` all run the R-4 suite and reject a failing, un-acked plan with a named, fail-closed error before the queue is mutated. `init-queue`'s current standalone `intake_validation_errors` call (in `src/aet/queue.py`) is subsumed by the full suite so the structural and semantic gates share one enforcement point.
- **R-7**: `work_class` becomes a recorded plan-time attribute — an optional plan frontmatter key whose value is one of `trivial | normal | critical` (the `docs/PIPELINE.md` tiers). It is validated at intake (an invalid value is rejected as part of R-6; a **missing** value is treated as `unclassified`, which is never zero-review-eligible — fail-safe) and carried onto the task record so the ledger can attribute a merge to a class. `CONTEXT.md` and `docs/PIPELINE.md` are updated to record work class as a machine-readable attribute, not only a routing concept (the glossary currently pins "work class = the Trivial/Normal/Critical intake tiers"; this makes that tier a stored field).
- **R-8**: A **track-record reader** computes, per `work_class`, the clean-merge history from the telemetry archive (`~/.aet/telemetry/...`) and the history log (`.agents/work-history.jsonl`). A task counts as a **clean merge** when it reached `merged` (terminal) with every required stage verdict `pass` and **no** failed stage record and no rework (no re-entry from `failed`, no repeated stage run) for that task. The reader is surfaced as a read-only projection (`aet desk --eligibility`) reporting each class's clean-merge count and whether that class is currently zero-review-enabled.
- **R-9**: The **zero-review auto-merge mechanism exists and is OFF by default**. A policy (config file, location an implementation choice) names the zero-review-enabled classes; it is **empty by default**, so nothing auto-merges. When — and only when — a task's `work_class` is explicitly enabled **and** its class track record (R-8) meets the configured threshold, the orchestrator auto-transitions that task `awaiting_merge → merged` through the same merge + closure path as R-3, at the point it would otherwise leave the task for the human (`aet-work/bin/orchestrator`, the `awaiting_merge` transition around `:1517–1553`). Absent both conditions, the task waits for a human decision at the desk. The shipped default config satisfies "the zero-review mechanism exists and is off."
- **R-10**: The phase exit gate is demonstrated end-to-end and recorded in `docs/audits/` (matching the frh-14 / ewl-06 A-B-findings precedent): (a) an `awaiting_merge` task is reviewed and **merged from the desk**; (b) a plan that fails validation is **rejected at `aet-work add`** and does not enter the queue; (c) the zero-review mechanism is shown **present-but-off** — the default config auto-merges nothing — alongside a test proving that with a class explicitly enabled and its track-record threshold met, a task *would* auto-merge.
- **R-11**: Tests cover: desk `awaiting_merge` filtering, evidence-bundle attachment, and missing-verdict surfacing, plus the `--json` projection (R-1); risk-score determinism and ordering against fixed inputs (R-2); `desk merge` driving the closure path and `desk abandon` recording the transition, both failing closed on an unknown or non-`awaiting_merge` id (R-3); each validate check family including R-trace pass/fail and the ack escape hatch honoring vs. ignoring a reason-less ack (R-4, R-5); intake rejection of a failing un-acked plan via `add`, `init-queue`, and `sync` (R-6); `work_class` intake validation including the missing→`unclassified` fail-safe (R-7); track-record computation from a synthetic ledger (R-8); zero-review off-by-default merging nothing, and the enabled-and-qualified auto-merge path (R-9).
- **R-12**: **Autonomous merge is a fail-closed gate, encoded in code and governance — not skill prose.** A new ADR **extends** ADR-005's "Gates That Must Still Stop in Unattended Mode" with a category for autonomous merge (ADRs are immutable — extend, don't edit, exactly as ADR-027 extended ADR-005), mirrored in `docs/CONVENTIONS.md`. Skills are made **merge-neutral**: `aet-ship/SKILL.md` is scrubbed of the self-merge ambiguity the audit exploited — step 14's "after the PR is created and the user indicates it has been merged" must not be contradicted by the Key Principle "Non-interactive by default … without human input until something is wrong"; the human-merge boundary is stated unambiguously and no skill instructs an agent to run `gh pr merge`. Rationale is the ADR-020 razor: a self-merge skips the human gate → the boundary belongs in code/governance, never in load-bearing prose an AI interprets.
- **R-13**: **`aet setup` generates a per-provider merge-guard for the active harness.** `aet-setup` detects the operating harness (auto-detect `.claude/`, `.kimi-code/`, … with an explicit override, the way it already detects the stack) and generates a guard that refuses an agent-issued `gh pr merge` — realized as a **`PreToolUse`-class hook** so it holds even under session auto/bypass mode (a bare permission-deny does not, which is why the audit incident slipped through). The guard blocks **`gh pr merge` only** — it does not touch `git push`, so the legitimate closure push and normal branch pushes are unaffected (no sanctioned-vs-ad-hoc push disambiguation needed). This generalizes the existing self-contained generator pattern (`aet-setup/bin/hooks`, which writes the `.git/hooks/pre-push` shim, ewl-03) to a second, harness-scoped artifact. A documented **harness-adapter interface** is established; **Claude Code is the one implemented adapter** in Phase 4; an undetected/unsupported harness yields a named "no merge-guard adapter — deferred to Phase 6" gap, never a silent pass (fail-safe). The generated guard is the operator's harness config (gitignorable) — not AET litter in the shared tree, so Mode-1 non-invasiveness holds.
- **R-14**: Tests + rehearsal cover: the generated Claude-Code guard refuses an agent-issued `gh pr merge` while `aet desk merge` and a plain `git push` are unaffected (R-13); an unsupported harness surfaces the named Phase-6 gap rather than passing silently (R-13); the ADR-005 extension and its `docs/CONVENTIONS.md` mirror are present and `aet-ship/SKILL.md` no longer carries the merge-neutral-violating ambiguity (R-12); and the exit-gate rehearsal (R-10) additionally demonstrates the guard blocking a self-merge under simulated auto mode.

## User Stories

- As the owner at the start of a shift, I open `aet desk` and see every task awaiting my decision ordered by risk, each with its test results and review/security findings inline, so my scarce review minutes go to the riskiest work first instead of a flat alphabetical list (satisfies: R-1, R-2).
- As the owner, once I've read a task's evidence I merge it or abandon it right there — `aet desk merge <id>` / `aet desk abandon <id>` — without switching tools, and the desk refuses if I fat-finger an id that isn't actually awaiting review (satisfies: R-3).
- As a planner, when a plan is missing an R-trace, has acceptance criteria that just restate tasks, or cites an ADR that doesn't exist, `aet plan validate` tells me before the plan ever reaches the queue, and if a check is a deliberate exception I record the reason inline rather than silently bypassing it (satisfies: R-4, R-5).
- As the owner, a half-baked plan can no longer sneak into the sprint through `aet-work add` — the same quality bar applies at every door into the queue (satisfies: R-6).
- As the owner planning for a dark exit door, I label each plan's work class and the factory starts keeping per-class track records, so that later — on data, by my explicit decision — I can let a proven class merge itself; until I do, nothing auto-merges (satisfies: R-7, R-8, R-9).
- As the Phase 7 implementer, the zero-review mechanism and its per-class track-record reader are already built and tested, so enabling class #1 is a config change backed by the scoreboard, not new machinery (satisfies: R-8, R-9).
- As the owner running AFK under session auto mode, an agent **cannot** merge a PR around the toolkit — the guard `aet setup` installed refuses `gh pr merge` — so the human-merge decision the desk (R-3) and the zero-review default (R-9) both assume is actually enforced, not merely the default; the boundary lives in code and survives across sessions and agents (satisfies: R-12, R-13).

## Acceptance Criteria

- [ ] `aet desk` lists exactly the `awaiting_merge` tasks, each showing its `qa`/`review`/`cso`/`sync-docs` verdicts (pass/fail, findings count, test totals) with any missing required verdict flagged as a gap; `aet desk --json` emits a machine-readable projection (satisfies: R-1).
- [ ] Given two `awaiting_merge` tasks differing only in `work_class` (critical vs. trivial) or in review-findings count, the desk orders the higher-risk one first and prints the factors that produced the ranking; the ordering is identical across repeated runs on the same inputs (satisfies: R-2).
- [ ] `aet desk merge <id>` on an `awaiting_merge` task drives it to `merged` via the existing closure path; `aet desk abandon <id> --reason "…"` records `abandoned`; both exit non-zero with a named error for an unknown id or a task not in `awaiting_merge` (satisfies: R-3).
- [ ] `aet plan validate` fails a plan that has an in-scope R-id with no covering task, an acceptance criterion that only restates a task, a new source file with no named test, or a `docs/adr/NNN` reference that resolves to no file; it passes a clean plan (satisfies: R-4).
- [ ] A plan that would fail R-4 passes validation when — and only when — it carries `⚠️ VALIDATE ACK: <check-id> — <reason>` for that check with a non-empty reason; a reason-less ack does not override (satisfies: R-5).
- [ ] `aet-work add`, `init-queue`, and `sync` each refuse a failing, un-acked plan with a named fail-closed error and leave the queue unmutated; a clean or fully-acked plan is admitted as before (satisfies: R-6).
- [ ] A plan frontmatter `work_class: critical` is accepted and recorded on the task; `work_class: urgent` is rejected at intake; a plan with no `work_class` is admitted as `unclassified` and is reported never-eligible by `aet desk --eligibility` (satisfies: R-7, R-8).
- [ ] Against a synthetic ledger where a class has N clean merges, `aet desk --eligibility` reports that class's clean-merge count and its (disabled) zero-review status (satisfies: R-8).
- [ ] With the default (empty) policy, an `awaiting_merge` task of any class is left for the human — nothing auto-merges; with a class explicitly enabled and its track record at/above threshold, an equivalent task auto-transitions to `merged` through the closure path (satisfies: R-9).
- [ ] The R-10 rehearsal — (a) desk merge, (b) intake rejection, (c) zero-review present-but-off with the enabled-and-qualified test — is executed and written up in `docs/audits/` (satisfies: R-10, R-11).
- [ ] A new ADR extends ADR-005's must-stop list with autonomous merge (ADR-005 left immutable), mirrored in `docs/CONVENTIONS.md`; `aet-ship/SKILL.md` states the human-merge boundary unambiguously and no longer contradicts it with "non-interactive by default," and instructs no `gh pr merge` (satisfies: R-12).
- [ ] After `aet setup` on a repo using Claude Code, an agent-issued `gh pr merge` is refused by the generated guard even under auto/bypass mode, while `aet desk merge` and a plain `git push` succeed unchanged; a repo whose harness has no adapter prints the named "deferred to Phase 6" gap instead of silently allowing the merge (satisfies: R-13, R-14).
